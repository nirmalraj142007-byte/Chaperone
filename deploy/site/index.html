Chaperone

An assistant re-reads the instructions for every tool it owns each time it connects, and remembers nothing about what they said last time. Chaperone is that memory: a context-aware add-on that keeps state across sessions, so a resident approves a tool once and is asked again only if what the tool claims it does changes.

When a tool's own wording changes, the resident sees the sentence they approved beside the one that replaced it, before anything runs.

Try it

  1. 1. Open the MCP Inspector

    Any MCP client works; the Inspector is the quickest. Run npx @modelcontextprotocol/inspector on your machine and open the address it prints.

  2. 2. Connect to this server

    https://chaperone-demo.duckdns.org/mcp

    Choose the Streamable HTTP transport and paste that address. MCP specification 2025-11-25; no sign-in.

  3. 3. List the tools

    Behind the server is a staged household grocery server, so its tools appear as grocery__add_item, grocery__read_list and so on, beside Chaperone's own chaperone/pending_changes. The namespacing {upstream}__{tool} is deliberate and asserted in the conformance suite.

  4. 4. Call grocery__add_item, then grocery__read_list

    Add an item by name, then read the list back. These are approved tools, so they run straight away.

  5. 5. Call chaperone/pending_changes

    It lists any tool whose description has changed since the household approved it. Most of the time the answer is none.

  6. 6. See a held tool

    A tool whose wording has changed is withheld from the list until the resident decides, and only that tool; every other tool keeps working. The held state is shown in the demo video (link below) and in the local run, which needs Docker and Node 24 and no AWS account: follow the README quickstart.

    If you happen to catch a tool mid-change on this server, please don't click Approve or Block on its card: this is the shared judging instance, and that decision belongs to the one demo household.
